# money-manage 专项测试报告

## 范围

本轮只新增测试与报告，没有修改生产代码。覆盖税费到卡工资、父母支出与赡养老人扣除隔离、统一支出计算、未来快照、资产口径、分期年月转换、场景前后对比、百分比滑条转换契约和 autosave。

## 执行

```bash
npm test
```

## 结果

已实际覆盖并可执行：

- 税前收入、个人五险一金、个税和税后到卡工资的计算链路；
- 五险一金个人/公司比例独立计算，包含公积金个人 12%、公司 5%；
- 租房和赡养老人按政策扣除比例与具体金额计算；
- 父母上交固定金额和收入百分比只进入现金流；
- 父母上交不会进入税前扣除；
- 固定月度、收入百分比、一次性和停用支出；
- 多项支出合计。
- 快照按日期生效、最近快照对比和 30 年 / 指定月份模拟窗口；
- 现金流击穿默认阻止保存，明确确认后才允许保存；
- 分期期限按月 / 按年统一换算；
- 场景覆盖不修改基准档案；
- input 后立即写 localStorage，blur 后 flush 服务端请求。

明确无法验证且已标记为跳过：

- `ExpenseItem` 的新增、编辑、删除持久化 CRUD：当前没有 repository、API 或服务导出；
- 现金资产 `0..2,000,000`、理财资产不超过总资产、年化收益率 `0..100%` 和百分比/数值滑条转换：当前没有统一资产校验或 slider 工具导出；
- 场景的完整 30 年差异走势：当前已有 override 基础能力，但尚未有统一的长期模拟结果比较器。

## 当前风险

1. 个税领域目前是“月度边际税率估算”，不是完整的年度累计预扣法；测试不能证明正式纳税申报口径正确。
2. 广东城市、纳税年度和专项附加扣除政策目录尚未完全接入 `calculateTax` 的输入校验链路；规则版本需要税务口径确认。
3. `domain/expense/index.ts` 的分期支出当前只取还款计划第 1 个月，未根据 `context.month` 推进完整的起止月份；长期健康曲线接入前存在月度结果失真的风险。
4. `domain/expense/index.ts` 将分期计划转换为 `as never`，削弱了 TypeScript 的契约检查。
5. Next.js 页面尚未接入上述统一领域模型、CRUD、资产约束、场景模拟和持久化能力，因此页面端到端行为未验证。
6. 测试依赖 Node 的 `--experimental-strip-types`；真实浏览器滑块拖拽和页面级保存时序仍需 E2E 测试。

## 结论

税费到卡工资、父母现金支出与赡养老人专项扣除隔离、基础支出计算、快照风险确认、年月转换、场景基准隔离和 autosave 基础流程已覆盖。资产约束、slider 转换、CRUD 和完整长期走势属于当前生产能力缺口，已明确保留为跳过的契约测试，不能宣称已通过。
